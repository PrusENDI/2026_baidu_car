# 循迹 CNN 数据最小采集说明书

本说明书只用于采集一整圈前置摄像头循迹数据。每次采集结束后，必须把数据保存为独立会话，防止下一次采集覆盖。

## 1. 采集前检查

开始前确认：

- 车辆、前置摄像头和蓝牙手柄连接正常；
- 赛道上没有人员和障碍物；
- 前置摄像头画面方向、清晰度和曝光正常；
- 车辆从计划的起点开始，车身方向与赛道一致；
- 项目根目录下没有需要保留的旧 `dataset/image_set_lane`。

如果 `dataset/image_set_lane` 中有旧数据，先按第 5 节保存旧会话。不要直接覆盖。

## 2. 启动采集程序

进入项目根目录并运行：

```bash
python collect_data.py
```

程序启动后确认没有以下错误：

- 找不到蓝牙手柄；
- 前置摄像头读取失败；
- 数据保存目录创建失败。

## 3. 采集一整圈

1. 将车辆放在起点并对正赛道。
2. **按住手柄按键 3**，开始记录前置摄像头图像和车辆状态。
3. 保持按键 3，人工驾驶车辆完成一整圈。
4. 回到终点后松开按键 3，停止记录并保存 `data.json`。
5. 将摇杆回中，确认车辆停止。
6. 同时按下 **L1+L2**，安全退出程序。

采集期间不要同时按其他功能键，否则可能停止记录或触发删除操作。

## 4. 驾驶要求

- 直道：保持居中，不做无意义的左右摆动。
- 十字路口：两次都直行，只做必要的小幅纠偏。
- 左直角：使用连续、平滑且尽量一致的左转操作。
- 锐角右拐：提前减速并平滑右转，不要突然打满摇杆。
- 全程尽量保持相同的驾驶习惯和入弯位置。

以下数据不能作为有效训练数据：

- 车辆冲出赛道或走错方向；
- 十字路口误入侧路；
- 锐角右拐失败或碰撞边界；
- 摄像头被遮挡、严重模糊或曝光异常；
- 车辆被人工抬起、拖动或长时间停车。

如果整圈驾驶明显失败，保留原始数据作为问题记录，但不要放入有效训练会话目录。

## 5. 保存为独立会话

必须在采集程序完全退出后执行。

以下示例把第一次有效采集保存为 `lap_001`：

```bash
mkdir -p dataset/lane_sessions
test ! -e dataset/lane_sessions/lap_001
mv -- dataset/image_set_lane dataset/lane_sessions/lap_001
```

每次使用新的会话编号：

```text
lap_001
lap_002
lap_003
...
```

下一次启动 `collect_data.py` 时，程序会重新创建 `dataset/image_set_lane`。

如果 `test ! -e` 没有成功，不要执行移动命令；先换一个未使用的会话编号，避免覆盖已有会话。

## 6. 最小验收

检查会话目录：

```bash
test -f dataset/lane_sessions/lap_001/data.json
find dataset/lane_sessions/lap_001 -maxdepth 1 -type f -name '*.jpg' | wc -l
python -c "import json; print(len(json.load(open('dataset/lane_sessions/lap_001/data.json'))))"
```

验收要求：

- `data.json` 存在并能正常读取；
- JPG 图片数量大于 0；
- JSON 记录数量大于 0；
- 图片数量与 JSON 记录数量一致；
- 抽查起点、十字路口、左直角、锐角右拐和终点图片均正常。

满足以上要求后，该圈才能作为一个有效采集会话。

## 7. 三条必须遵守的规则

> **不要反复向同一个 `dataset/image_set_lane` 目录采集，多次启动可能覆盖旧图片。**

> **不要对需要保留的数据使用“清空全部”功能。**

> **错误驾驶的一整圈不要混入有效训练数据。**
