# X/Y 复位协作式调度设计

## 目标

将 `ArmController.reset_position()` 当前的 X/Y 双线程复位改为单线程协作式调度。X 和 Y 在机械上仍可同时运动，但所有 MC602 串口事务由同一调度循环按优先级顺序执行，避免两个线程争用串口锁并随机拖慢 X 轴限位检测和速度刷新。

本改动只调整 `reset_position()` 发起的联合复位。现有 `reset_x()`、`reset_y()`、普通 X/Y 定点移动公共接口保持兼容；AI1 读数持续为低电平的现场硬件问题不在本改动中处理。

## 调度原则

1. X 轴安全优先：每轮先处理 X 的新鲜 AI1 采样和必要的速度心跳。
2. X 编码器继续按约 200 ms 降频读取，停滞仍按真实时间判断。
3. Y 轴复位拆为可暂停的单步操作，仅在 X 本轮关键事务完成后推进一次。
4. 不并发调用 MC602；不新增独立速度心跳线程。
5. 调度循环不得用固定长睡眠阻塞 X，空闲等待只允许使用有上限的短间隔。

## 状态与数据流

联合复位开始时先发送手部 `UP` 和机械臂 `RIGHT` 姿态命令，然后初始化 X、Y 两个复位状态。

X 状态依次为：停止确认、启动松开确认、负向寻零、静止限位确认、建立零点、安全回收、完成。X 寻零期间每轮先读取新鲜 AI1；只有 AI1 仍为松开状态时才能再次发送负速度。触发、编码器异常或编码器停滞均沿用现有零速确认及 500 ms 静止 AI1 连续确认逻辑。建立零点后，X 转入 15 mm 安全回收。

Y 状态依次为：初始化、向复位方向运动、限位或目标到达、停止、完成。每次 Y 调度只执行一次位置读取、PID 计算、速度下发或限位检查，不在内部运行阻塞循环。

调度器在 X、Y 都完成后保存位置并返回成功。

## 错误处理

- 任一轴出现串口异常、参数异常或超时，联合复位立即进入失败清理。
- 失败清理向 X、Y 下发零速；X 仍使用已有的新响应确认机制。
- X 未完成机械归零时不得建立零点，也不得执行安全回收。
- Y 失败不得掩盖 X 失败，错误信息应包含轴、阶段和原始异常。
- `reset_position(rehome_x=False)` 跳过机械寻零，但 X 安全回收和 Y 复位仍由同一调度器推进。

## 兼容性

- `reset_position(rehome_x=True)` 的参数和返回语义保持不变。
- `reset_x()` 与 `reset_y()` 仍可被单独调用。
- 普通 `move_x_position()`、`move_y_position()` 不在本次改动范围内。
- 不修改 MC602 协议、硬件端口、归零阈值、速度或超时配置。

## 验证

按当前约束不新增专项测试，也不执行真实电机测试。完成代码后只执行离线语法编译和 `git diff --check`；现场联合复位由用户在 Orin 旁看护验证。日志应能看出 X 最大速度刷新间隔、X/Y 完成阶段以及失败轴和阶段。
