## 遇到的问题

### 1. `collect_data.py` 启动前触发 Paddle/sklearn 报错

`collect_data.py` 使用：

```python
from smartcar import logger
from smartcar import CollectControlCar, Camera
```

这会先执行 `smartcar/__init__.py`，进而提前导入 Paddle、Ernie、sklearn 等推理相关模块。Orin 上报错为：

```text
ImportError: scikit_learn.libs/libgomp... cannot allocate memory in static TLS block
```

结论：采集脚本还没真正创建摄像头和车控对象，就被包根的重导入拖入推理栈。

### 2. 两个摄像头已物理识别，但项目逻辑编号和 udev 名称不一致

Orin 实际设备：

```text
/dev/cam1 -> /dev/video4
/dev/cam4 -> /dev/video2
```

原代码 `Camera(2)` 固定查找 `/dev/cam2`，因此报：

```text
摄像头/dev/cam2不存在
```

结论：不是第二个摄像头没识别，而是第二个摄像头当前被 udev 命名为 `/dev/cam4`。

### 3. 旧进程可能占用硬件

早前状态中曾看到旧进程：

```text
/usr/bin/python3 /home/jetson/code_vehicle_wbt/car_start.py
```

它曾占用 `/dev/ttyUSB0` 和 `/dev/video0`。后续测试前需要确认没有旧进程占用串口和摄像头。

## 本地修改

### 1. 新增安全启动脚本

新增：

```text
smartcar/whalesbot/tools/collect_data_safe_start.py
```

作用：

- 不修改 `collect_data.py`、`collect_control.py`、`smartcar/__init__.py`。
- 绕开 `smartcar/__init__.py`，避免启动前导入 Paddle/sklearn。
- 直接加载 `camera.py` 和 `collect_control.py`。
- 为原车控模块所需的 `logger`、`PID`、`CountRecord`、`get_yaml`、`IndexWrap`、`limit_val` 建立轻量工具导出。
- 支持 `--preflight-only`，只检查摄像头和端口，不进入车体主循环。

运行方式：

```bash
cd /home/jetson/workspaces/baidu_car_2026_official_run_copy
python3 smartcar/whalesbot/tools/collect_data_safe_start.py --preflight-only
python3 smartcar/whalesbot/tools/collect_data_safe_start.py
```

注意：第二条会进入真实车体控制流程，启动底盘、机械臂、蓝牙手柄、蜂鸣器和采集主循环。

### 2. 摄像头路径兜底

修改：

```text
smartcar/whalesbot/tools/camera.py
```

新增逻辑：

- 优先使用 `/dev/camN`。
- 如果 `/dev/camN` 不存在，则扫描实际存在的 `/dev/cam*`。
- 对 `Camera(2)`，若存在两个项目摄像头 `/dev/cam1`、`/dev/cam4`，自动使用第二个，即 `/dev/cam4`。

## 风险和后续

- 新脚本是新增入口，不会进入 `collect_data.py` 文件本身，但会执行等价的采集启动逻辑。
- 后续如果希望仍从 `collect_data.py` 进入，需要改 `collect_data.py` 的导入方式；本轮按要求没有这样做。
- `smartcar/__init__.py` 仍然保留原始重导入行为，所以旧入口仍可能触发 Paddle/sklearn 报错。
- `Camera(2)` 自动映射依赖 `/dev/cam*` 的排序；当前 Orin 上适配 `/dev/cam1` 和 `/dev/cam4`。
