# 循迹测试数据快速对比方法

## 目标

用固定、可复核的步骤比较 `safe_lane_test.py` 产生的测试数据，先用 CSV 缩小证据范围，再做少量关键帧视觉核验。避免重复全量扫描视频，也避免把 MP4 播放时间误当作真实测试时间。

本方法只用于离线分析和提出验证方案。没有车身真实轨迹、外部视频或用户事件标注时，不直接修改 PID、模型、横向补偿或锐角策略。

## 输入与边界

每个录制目录通常包含：

```text
logs/orin/lane-tests/<session>/
  annotated.mp4
  frames.csv
  metadata.json    # Ctrl+C 或异常情况下可能缺失
```

- Windows 是分析和文档编辑端。
- 默认只分析已经拉到本地的文件。
- 本地无法解码视频时，不自动访问 Orin；必须得到用户允许后，才可在 Orin 上只读解码并以内存结果返回。
- 不反向同步 Orin 源码，不清理远端数据。

## 快速流程

### 1. 只处理新增或变化的文件

先比较录制目录、文件大小和修改时间。仅当远端文件新增或大小变化时才重新拉取。重要测试在拉取后比较远端与本地 SHA-256；哈希一致后，不重复传输或校验视频内容。

特别注意：仍在录制或尚未关闭的 MP4 可能继续增长。旧的本地副本小于远端时，应补齐后再分析。

### 2. 先读 metadata 和 CSV，不先扫视频

每段录制固定汇总以下项目：

| 类别 | 指标 |
| --- | --- |
| 完整性 | CSV 行数、首末 `frame_index`、帧号是否连续、`video_written=false` 数量 |
| 时间 | 最后一个 `elapsed_s`、有效循环频率 `(rows - 1) / elapsed_s` |
| 停止 | `stop_reason`、参数中的 `speed` 和 `duration` |
| 推理 | `infer_ms` 的 mean、p95、p99、max，以及 `>50 ms`、`>1000 ms` 数量 |
| 循环 | 排除第一帧后的 FPS p01、p05、median、min，以及 `<20 FPS` 数量 |
| 横向 | `error_y`、`vy` 的 mean/std/min/max，`abs(vy) >= 0.699` 数量 |
| 航向 | `error_angle`、`yaw` 的 mean/std/min/max，正负饱和数量 |

第一帧 `loop_fps` 是计时基准值，不能纳入性能结论。

### 3. 自动定位航向事件

默认使用两级阈值：

- PID 饱和：`yaw <= -1.499` 或 `yaw >= 1.499`。
- 大转向：`yaw <= -1.2` 或 `yaw >= 1.2`。

把连续大转向帧合并为区间，记录开始时间、结束时间、持续时间和帧数。快速视觉核验优先选：

1. 每个连续区间的峰值帧；
2. 区间起点和终点仅在需要判断进入/退出过程时追加；
3. 一帧直道基线；
4. 录制末帧，用于检查 Ctrl+C 或异常尾部。

单段首次核验限制在一张不超过 16 帧的联系表。只有关键帧仍无法解释事件时，才扩大到事件前后短窗口，避免全视频逐帧扫描。

### 4. CSV 时间必须映射到 MP4 帧号

`annotated.mp4` 当前固定按 20 FPS 封装，但控制循环实际约为 57--63 Hz。视频播放器显示的秒数不是 CSV 的真实 `elapsed_s`，不能用 `CAP_PROP_POS_MSEC` 或播放器时间直接寻找控制事件。

正确方法：

```python
row = df.loc[(df["elapsed_s"] - target_s).abs().idxmin()]
frame_index = int(row["frame_index"])
capture.set(cv2.CAP_PROP_POS_FRAMES, frame_index)
```

视觉结论中同时记录：

```text
session + CSV elapsed_s + frame_index + yaw + error_angle
```

这样即使 MP4 播放速度不正确，也能复现同一控制帧。

### 5. 视觉对比只回答可见问题

关键帧主要检查：

- 直道、普通弯、锐角、分岔或交叉标线；
- 单侧边界是否占据主要视野；
- 是否存在运动模糊、遮挡、立柱或其他高对比物体；
- 大角度输出是否有明确视觉诱因；
- 相邻关键帧是否出现方向快速反转。

前视车载画面通常不能单独量化车辆相对赛道中心的位置。没有外部俯视/后视视频、相机标定或车身投影基准时，不把“看起来靠左”写成“已经证明左压线”。

## PID 与后处理判断门槛

| 证据组合 | 优先判断 | 暂不采取的动作 |
| --- | --- | --- |
| `error_y` 接近零，但外部视频确认持续偏左 | 模型零点、相机几何或坐标基准 | 不用增大横向增益掩盖零点问题 |
| 横向命令持续要求纠偏，但车辆不回正 | 底盘响应、速度映射或横向 PID | 不先改模型零点 |
| 航向命令饱和且车辆仍转不过去 | 先验证减速和底盘转向能力 | 不继续提高已被限幅的 P |
| 模型角度单帧跳变，道路画面稳定 | 候选：滤波、持续性确认、变化率限制 | 未测延迟前不直接上线滤波 |
| 大角度连续出现且画面确为锐角 | 候选：饱和感知减速或锐角策略 | 不把连续真实弯道当噪声滤掉 |
| 命令后出现明显过冲/反打 | 才考虑降低航向 P 或限制变化率 | 没有车身响应证据时不凭命令猜过冲 |

精确 PID 数值必须通过相同路线、相同速度、一次只改一个变量的 A/B 实车测试确定。测试仍由用户执行。

## 已知录制注意事项

- MP4 固定 20 FPS，而每个控制循环写一帧，因此 MP4 播放时长约为真实测试时长的 2.8--3.2 倍。分析一律按 CSV `frame_index` 对齐。
- Ctrl+C 可能恰好发生在视频写入和 CSV 写入之间。已观察到一段 MP4 尾部包含 `frame=9562`，而 CSV 结束于 `frame_index=9561`。这种单帧差异应单独报告，不能误判为 rsync 损坏。
- 缺少 `metadata.json` 时，停止原因保持未知；不能根据 CSV 长度推断为正常到时。
- `frames.csv` 没有车辆实际位姿、轮速反馈或赛道中心真值，只能证明模型输出和下发命令，不能单独证明压线、过冲或底盘执行效果。

## 每次汇总的最小输出

1. 文件完整性和停止原因。
2. 每段录制一行核心统计。
3. 大转向/饱和区间列表。
4. 按 `frame_index` 核验的视觉场景说明。
5. 能确认、不能确认和仍缺少的证据。
6. 如需改参，先给单变量设计、速度、时长、停车保护和验收指标，得到用户确认后再实施。
