# 固定赛道 CV + 十字路口手柄长训设计

日期：2026-08-17

## 1. 目标与边界

本轮从原始 D4 action checkpoint 重新初始化，在固定赛道数据上进行 200 epoch 长训。目标是优先修正两个十字路口的错误转向，同时保留普通弯道、锐角和 CV 速度策略。跨场景泛化不是主要优化目标。

训练只使用以下 3468 帧：

```text
CV 训练数据                  2822
十字路口手柄数据              646
合计                         3468
```

`lap_002`、官方训练参考集和官方 eval 不进入训练，只用于 checkpoint 风险评估。现有 epoch 10、epoch 20 候选模型必须原样保留，本轮使用独立输出目录，不覆盖既有产物。本设计不授权部署 Orin。

## 2. 标签语义

模型输出保持：

```text
[speed_demand, kappa_action]
```

CV 样本同时监督两个输出：

```text
target_mask = [1, 1]
```

手柄样本只监督曲率：

```text
kappa_action = state[2] / max(abs(state[0]), 0.12)
speed_demand = 0  # 仅占位
target_mask = [0, 1]
```

手柄 `state[2]` 已是映射后发送给底盘的 `wz`，不得再次乘以 `3.14`、`0.3` 或其他手柄映射系数。手柄低速命令不进入速度损失。

车端语义仍为：

```text
speed_demand -> speed_curve -> actual_vx
wz = actual_vx * kappa_action
```

因此手柄低速不会直接把模型速度训练成 `0.1 m/s`，但较大曲率可能通过车端曲率减速间接降低 `actual_vx`。

## 3. 数据分组与采样

现有标签审计结果：

| 分组 | 总帧数 | `abs(kappa_action) >= 0.05` | 有效转向平均绝对曲率 |
|---|---:|---:|---:|
| CV | 2822 | 2045 | 1.6370 |
| 十字路口手柄 | 646 | 74 | 3.1237 |

手柄数据中只有 74 帧属于有效转向，其余 572 帧是入弯前、直行或回正后的零转向上下文。不能简单提高全部手柄样本的比例，否则会主要重复零转向帧。

训练数据分为三个互斥组：

1. `cv`：全部 2822 帧 CV 训练数据；
2. `manual_active`：74 帧满足 `abs(kappa_action) >= 0.05` 的手柄有效转向；
3. `manual_context`：其余 572 帧手柄零转向上下文。

每个 epoch 的目标采样比例为：

```text
cv               70%
manual_active    15%
manual_context   15%
```

batch size 为 64。实现时使用确定性分组采样日程，在相邻 batch 间轮换 `45/10/9` 和 `45/9/10`，使 epoch 级比例接近 `70/15/15`。三个组分别洗牌；组内样本用尽后独立重排并循环。随机种子写入训练报告，使长训可以复现。

速度损失仍只对 batch 中 mask 有效的 CV 样本计算，并按有效权重归一化；手柄采样比例变化不得稀释速度损失数值。

## 4. 损失与数据增强

损失保持双输出归一化：

```text
speed_scaled = speed_demand
kappa_scaled = kappa_action / 5.0

loss_speed = SmoothL1(speed_prediction, speed_demand)
loss_kappa = SmoothL1(kappa_prediction / 5.0, kappa_action / 5.0)
loss = loss_speed + 2.0 * loss_kappa
```

两个分量分别应用 `target_mask`，再按各自有效样本权重归一化。

水平翻转会构造固定赛道中不存在的镜像路线，模糊和噪声会削弱十字路口精确起转所依赖的线条，因此三阶段始终关闭：

```text
horizontal_flip = 0
模糊和噪声 = 0
```

同一固定赛道仍存在曝光、灯光和白平衡的小幅变化。为避免 200 epoch 完全记忆固定图像，同时不让只有 74 帧的手柄有效转向受到强增强干扰，光度增强按训练阶段启停：

```text
阶段 A（epoch 1–20）
  原图，不增强

阶段 B（epoch 21–160）
  每张图 30% 概率执行轻微光度增强：
  brightness = [0.95, 1.05]
  contrast   = [0.95, 1.05]
  saturation = [0.97, 1.03]
  hue_delta  = [-2, 2]

阶段 C（epoch 161–200）
  原图，不增强
```

阶段 B 未命中 30% 概率的样本保持完全原图。增强不得改变标签或 mask。当前默认 action 增强的亮度 `0.8–1.2`、对比度 `0.8–1.2`、饱和度 `0.85–1.15`、Hue `±8`、15% 模糊和 15% 噪声不用于本轮长训。训练状态和逐 epoch 报告必须记录实际增强 profile 与命中数量，使断点恢复后继续使用正确阶段。

## 5. 三阶段训练

统一配置：

```text
initial_checkpoint = 原始 D4
epochs = 200
batch_size = 64
kappa_weight = 2.0
checkpoint_interval = 5 epochs
device = gpu
```

### 阶段 A：输出头适配

Epoch 1–20：冻结卷积特征部分，只训练双输出头，学习率为 `1e-5`，输入使用原图。目标是先让输出层适配新的速度/曲率联合标签，避免一开始破坏 D4 已有视觉特征。

### 阶段 B：固定赛道主拟合

Epoch 21–160：解冻输出头和后部卷积层。输出头学习率为 `5e-6`，后部卷积层学习率为 `1e-6`。每张输入图像以 30% 概率应用第 4 节的小范围光度增强。这是主要拟合阶段，重点学习十字路口手柄纠正、普通弯道和锐角，并覆盖固定现场的正常光照波动。

### 阶段 C：全网络低学习率精修

Epoch 161–200：解冻全网络。输出头学习率为 `2e-6`，骨干网络学习率为 `2e-7`，输入恢复为原图。目标是低学习率贴近真实采集图像，调整起转、峰值、回正和速度恢复，不追求最后一轮训练 loss 最低。

阶段切换必须记录在训练状态中。恢复训练时从 checkpoint 中恢复模型、优化器、epoch、当前阶段、采样器随机状态和学习率组，避免恢复后重新执行错误阶段。

## 6. Checkpoint 与训练监控

每 5 epoch 保存：

- 模型参数；
- 优化器状态；
- 当前 epoch 和训练阶段；
- 分组采样计数与实际比例；
- 增强 profile 与实际增强命中数量；
- 分项训练损失；
- CV 与手柄有效 mask 计数；
- 评测报告。

出现以下任一情况时停止训练并保留现场，不自动跳过：

- loss 或模型输出出现 NaN/Inf；
- 某 epoch 任一采样组计数为零；
- 实际采样比例明显偏离设计比例；
- CV 速度有效样本计数不等于预期；
- 手柄样本意外进入速度损失；
- checkpoint 无法完整恢复阶段和优化器状态。

200 epoch 结束后不自动把最后一轮命名为最终模型。如果 200 epoch 时关键行为仍持续改善，可在用户确认后以相同 checkpoint 间隔续训。

## 7. 逐 checkpoint 评测

### 7.1 十字路口手柄 646 帧：最高优先级

每 5 epoch 对完整序列评测：

- 74 帧有效转向的方向正确率；
- 有效转向曲率 MAE、峰值和持续时间；
- 起转与回正位置；
- 572 帧零转向上下文的误转率；
- 整段曲率冲量；
- 相邻帧输出抖动。

这些数据参与训练，因此结果衡量固定赛道拟合程度，不作为泛化指标。

### 7.2 CV 独立验证圈 868 帧

评测：

- `speed_demand MAE`；
- `kappa_action MAE`；
- 普通弯道和锐角的方向、峰值与持续时间；
- 速度输出范围和弯道速度趋势。

### 7.3 车端后处理还原

对候选 checkpoint 使用实际 `speed_curve` 和真实 `dt` 还原：

```text
speed_demand -> actual_vx
wz = actual_vx * kappa_action
```

检查十字路口减速、弯中最低速度、实际角速度、出弯恢复和相邻帧变化。手柄集没有可信速度标签，不能把手柄 `0.1 m/s` 当作此项速度真值。

### 7.4 独立手柄参考集

继续对 `lap_002`、官方训练参考集和官方 eval 计算曲率 MAE、方向正确率、有效转向召回、零转向误转率和序列相关性。这些指标只作为风险参考；若固定赛道十字路口显著改善，不因独立参考集的轻微退化直接否决候选。

## 8. 模型选择与导出

不使用单一全局平均分。选择优先级为：

```text
十字路口纠正
-> 普通弯道和锐角无严重退化
-> 车端减速与恢复合理
-> CV 平均误差
-> 独立手柄集参考指标
```

离线评测后最多保留三个候选：

1. 十字路口纠正最佳版；
2. CV 行为保持最佳版；
3. 两者折中版。

若同一 checkpoint 同时满足多个角色，则合并候选。每个候选导出静态模型，并验证动态/静态最大差异不超过 `1e-5`。导出报告必须包含 checkpoint epoch、训练阶段、输入输出语义、数据哈希、训练配置、评测摘要和产物 SHA256。

最终 checkpoint 仍须通过低速固定赛道闭环实车对比，重点检查两个十字路口、普通弯道、锐角、入弯减速和出弯恢复。未经用户明确授权不得部署到 Orin。

## 9. 实现与测试要求

训练入口需要补齐并隔离以下能力：

- 三组确定性采样器；
- 按 epoch 切换冻结范围和参数组学习率；
- 可完整恢复的训练状态；
- 每 5 epoch checkpoint 和分组评测；
- 车端速度后处理离线还原；
- 候选 checkpoint 排序与导出报告。

至少增加以下自动化测试：

1. 采样器在多个 epoch 内满足目标比例且三个组均被采样；
2. `manual_active` 与 `manual_context` 按 `0.05` 阈值互斥且覆盖全部 646 帧；
3. 阶段 A/C 对同一输入不做增强，阶段 B 只在 30% 概率门控后使用批准的小范围光度参数；
4. 水平翻转、模糊和噪声在三个阶段始终不会执行；
5. 手柄样本不产生速度梯度；
6. 三个训练阶段只更新预期参数；
7. 各阶段学习率、增强 profile 与 epoch 边界正确；
8. 从阶段 A、B、C checkpoint 恢复后状态一致；
9. NaN/Inf、空分组和错误 mask 会触发明确失败；
10. 每 5 epoch 生成完整且可读取的评测报告；
11. 动态/静态导出一致性阈值为 `1e-5`。

正式 200 epoch 长训前，必须先运行单元测试和 2 epoch GPU smoke。smoke 只验证数据流、采样、冻结、损失、checkpoint 和恢复，不用于选模型。
