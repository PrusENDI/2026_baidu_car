# 默认任务按键启动设计

## 目标

程序完成现有初始化后，等待控制器物理按键 1；只有检测到按键 1 才执行 `car_start_2026.py` 当前默认任务。按键 3 可停止当前任务，任务返回后再次按键 1 可重新执行默认任务；按键 2、4 不启动任务。

## 现状与约束

- `car_start_2026.py` 是人工启动入口，默认任务由其中现有调用决定。
- `MyCar` 已通过 `config_car.yml` 的 `io.key` 初始化当前工作区的 `Key4Btn`。
- `MyCar` 当前会启动后台按键线程；新增等待逻辑不能再无协调地创建第二个按键读取线程。
- 不复制旧项目 `Baidu_code` 驱动，不恢复旧项目多任务菜单或 systemd 按键启动监督器。

## 设计

在当前按键线程中增加一个简单的启动事件：检测到按键 1 时设置事件，`car_start_2026.py` 在调用默认任务前等待该事件。这样保持与 `Ts_run/go.py` 相同的“没有按键就等待”行为，同时不创建第二个按键读取线程。

启动入口在初始化后保持一个简单外层循环。每轮开始前清除上轮启动事件并复位 `_stop_flag`，按键 3 导致当前任务返回后，下一轮重新等待按键 1。

## 错误处理

- 控制器持续返回 0 时保持等待，不执行默认任务。
- 收到按键 1 后放行并继续默认任务。
- 本次不增加超时、断线恢复或复杂退出协议，按现有 `Ts_run` 行为保持阻塞等待。

## 测试

- reader 依次返回 0、2、1 时，门控只在 1 出现后放行。
- reader 只返回 0 且触发停止/超时时，门控不放行。
- 启动入口在门控未放行时不调用默认任务，在放行后调用一次。
- 运行现有测试集及语法检查。
