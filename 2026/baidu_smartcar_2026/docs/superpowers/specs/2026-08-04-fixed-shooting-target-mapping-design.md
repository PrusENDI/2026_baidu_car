# 固定射击靶位映射与击倒确认设计

## 目标

射击任务必须把识别阶段的 `animal_list[0..3]` 与射击阶段的四个物理靶位一一对应。车辆在任何时刻都应知道正在处理的逻辑靶位索引，不能在每一帧把行进方向最靠边的检测框重新编号为第 0 靶。

## 靶位校准与身份

- 射击入口处等待连续三帧同时识别到四个 `animal`。
- 每帧按车辆行进方向排序；连续三帧顺序与位置稳定后锁定为 `target[0]` 到 `target[3]`。
- 普通 YOLO 的 `obj_id` 均为 0，不能作为身份。任务内使用固定顺序、相邻帧位置连续性和已确认击倒集合维持逻辑身份。
- 射击计划保存 `(target_index, move_distance)`，不得只保存距离。
- 已确认击倒的靶允许消失；其余站立靶继续按固定物理顺序映射，不重新从 0 编号。

## 单靶闭环

1. 车辆按计划驶向明确的 `target_index`。
2. 从固定靶位映射取得该索引的检测框并完成视觉对齐；检测框必须保持相邻帧连续，禁止跳到相邻靶。
3. 发射一发并等待 5 秒。
4. 连续三帧确认当前靶消失且其余靶顺序一致，才标记为 `shot`。
5. 若当前靶仍存在，则重新关联、重新对齐并重试；每个靶最多发射四发。
6. 四发后仍未击倒，记录失败并继续后续目标。

## 宽松恢复与安全边界

- 单帧漏检、额外框或位置异常只丢弃该帧，不清空已锁定映射。
- 关联或对齐失败时停车并在限定时间内恢复；持续失败则记录当前靶失败并继续下一靶。
- 击倒确认无法判断时延长恢复；仍不明确则记录 `verification_ambiguous`，不向可能已经倒下的位置盲目补射。
- 单靶失败不终止整个射击任务。只有尚未建立初始四靶映射时禁止开始射击。

## 日志

统一输出 `[TARGET_SHOOTING]` 结构化日志，包含 `event`、`stage`、`target_index`、`attempt`、候选框 `dx`、靶位映射、耗时和失败原因。

主要失败原因包括：`calibration_timeout`、`association_timeout`、`association_ambiguous`、`alignment_timeout`、`shot_command_error`、`knockdown_not_confirmed`、`verification_ambiguous` 和 `max_shots_exhausted`。

任务结束输出 `TASK_SUMMARY`，列出计划、成功、失败、跳过靶位及各靶发射次数。

## 验收标准

- 四靶同时可见时连续三帧锁定固定的行进方向索引。
- `animal_list[i]` 只控制 `target[i]`，射击对齐不能跳到相邻索引。
- 靶倒下后剩余靶保持原索引。
- 未击倒时最多发射四发；单靶失败后继续后续计划。
- 日志能够区分关联、对齐、发射、击倒确认和达到发射上限等失败阶段。
