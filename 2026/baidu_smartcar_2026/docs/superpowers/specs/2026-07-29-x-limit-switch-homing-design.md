# X 轴微动开关机械归零设计

## 目标

用 MC602 的 AI1 专用模拟输入和外接 COM+NC 微动开关，替换 `reset_x()` 当前把编码器停滞/机械堵转视为归零成功的逻辑。只有开关连续稳定触发后才允许建立 X 轴机械零点。

本阶段只修改水平轴归零路径、安全回收路径及其配置，不改变普通 `move_x_position()` 的零点语义，不修改舵机 angle16 协议，也不执行真实电机或位置测试。

程序每次启动只执行一次机械归零。机械零点建立后，水平轴立即离开开关并停在 `x=0.015 m`；本次运行后续需要回收水平轴时只返回该安全位置，不再重复触发微动开关。

## 已确认现场参数

- 控制器：MC602。
- 端口：AI1，使用现有 `AnalogInput2` / `sensor_analog_a` 路径。
- 接线：COM+NC。
- 松开：`raw=0`。
- 按下：`raw` 范围为 4010–4036，典型值约 4023。
- 断线：按现场决定暂按约 4023 处理，与按下同为高电平。
- 阈值：2000。
- 有效方向：`above`。
- 连续稳定样本数：5。

## 已接受的硬件限制

COM+NC 两线接法下，开关按下和线束断线都会呈现高电平，软件无法仅凭 AI1 区分二者。

- `reset_x()` 启动时若不能连续确认低电平松开状态，则立即停止并返回 `False`，不执行任何 X 轴运动。
- 启动时已经断线会因此安全失败。
- 用户选择单次触发方案：启动确认低电平后低速回收；首次出现高电平时立即停止 X 轴，再在静止状态下完成连续高电平确认。
- 静止确认期间任一样本回落为低电平，都保持停止并返回 `False`，不恢复运动，也不增加退离或二次触发流程。
- 因此，线束若恰好在回收运动过程中从低电平变为高电平，软件可能把断线位置视为触发位置。这是本设计明确接受的现场限制，不增加退离、释放确认或二次触发流程。

## 配置

在 `arm_cfg.yaml` 的 `horiz_cfg` 下增加独立 `homing` 配置：

```yaml
horiz_cfg:
  homing:
    limit_port: 1
    active: above
    threshold: 2000
    stable_samples: 5
    speed: 0.06
    timeout: 8.0
    safe_position: 0.015
```

`speed` 是向机械回收方向运动时使用的速度绝对值；实际命令为负值。`timeout` 是整个归零动作的最长时间。`safe_position` 是成功建立机械零点后以及任务过程中使用的安全回收位置，固定为 `0.015 m`。配置初始化时验证端口、有效方向、阈值、样本数、速度、超时和安全回收位置；无效配置不得启动归零或安全回收运动。

## 单次归零与安全回收策略

### 零点有效状态

`ArmController` 增加仅在当前进程内有效的 `x_zero_valid` 状态：

- 初始化时为 `False`，不得因为 YAML 中保存过历史位置而恢复为 `True`。
- 只有 `reset_x()` 连续稳定读到开关触发、写入 `x_pose_start` 并清零 X 状态后才置为 `True`。
- 启动采样失败、停滞、超时、串口异常或传感器异常均不得把它置为 `True`。
- 普通 `move_x_position()` 和安全回收不得重新定义零点。

该状态确保未经本次启动真实机械归零时，任务代码不能仅凭编码器历史值执行安全回收或切侧。

### 安全回收

新增统一的安全回收方法，例如 `retract_x_safe()`。它负责：

1. 确认 `x_zero_valid` 为 `True`，否则立即失败且不运动。
2. 调用普通位置运动移动到配置的 `x=0.015 m`，并检查其布尔结果。
3. 到位后读取新鲜 AI1 样本，只有连续 5 个低电平样本确认开关已经释放才返回 `True`。
4. 位置运动失败、开关未稳定释放、读数无效或串口异常时停止 X 轴并返回 `False`。

安全回收只使用已经建立的零点，不修改 `x_pose_start`。它的成功语义是“编码器到达 1.5 cm 且微动开关稳定释放”，不是重新建立零点。

### 启动流程

`init()` 保留一次完整 `reset_position()`。其中 X 轴流程为：

1. 调用 `reset_x()` 建立本次启动唯一可信的机械零点。
2. 归零成功后立即调用安全回收，使水平轴停在 `x=0.015 m` 并确认开关释放。
3. 机械归零或安全回收任一步失败，都停止初始化并禁止进入任务。

`reset_position()` 增加保持现有无参调用兼容的 `rehome_x=True` 参数。默认值仍执行上述启动机械归零；需要重置 Y 轴但本次运行已经建立 X 零点时，调用方显式使用 `rehome_x=False`，此时 X 轴只执行安全回收。

### 任务调用点

`car_task_function.py` 中现有重复 `reset_x()` 调用改为统一安全回收，包括播种、水塔、作物采收和分拣存储流程。`get_order()` 中再次执行的完整 `reset_position()` 改为 `reset_position(rehome_x=False)`，保留 Y 轴重置，但 X 轴不再机械归零。

任务中明确用于“完全收回再切侧”或“任务结束回收”的位置调用改为安全回收。不能把所有 `move_x_position(0)` 批量替换为 1.5 cm：放球、放货等流程中的 `x=0` 可能是业务操作坐标，必须按调用语义逐处判断并保持其原目标。切侧前的既有特殊避障位置（例如先移动到 `x=0.20 m`）也继续保留；完成切侧后若需要回收，则使用 `retract_x_safe()`。

任一安全回收失败都必须终止当前任务，不得继续旋转机械臂、下降、抓取或释放。

## 组件边界

### 传感器初始化

`x_params_init()` 接收 `homing` 配置并创建一个 `AnalogInput2(limit_port)`。该对象只读取 AI1，不实例化额外电机。

### 新鲜采样

增加 X 限位读取辅助方法。每次读取前清空 MC602 专用模拟输入实例的 `last_data`，然后调用高层 `AnalogInput2.read()`：

- 本次事务无新响应时失败，不复用缓存旧值。
- 返回值不能转换为有限浮点数时失败。
- 串口或解析异常向 `reset_x()` 报告失败。

### 状态判断

使用配置中的 `active` 和 `threshold` 判断当前样本：

- `active: above` 时，`raw >= threshold` 为触发。
- `raw < threshold` 为松开。
- 连续 5 个同方向样本才视为稳定状态。

## `reset_x()` 状态机

`reset_x()` 继续接受无参数调用，以及现有 `out_time`、`speed_limit` 关键字参数。未显式传入时使用 YAML 的 `timeout` 和 `speed`；显式参数用于兼容现场调用并覆盖对应配置。

1. 进入函数后立即执行 `x_speed(0)`，重置停滞计数和位置差分基准。
2. 在不发送运动命令的情况下读取 5 个连续样本。只有全部为松开状态才继续；触发、断线、串口异常或不稳定状态均返回 `False`。
3. 以负向低速命令向机械回收方向运动。
4. 每个运动循环刷新负向低速命令、读取新鲜 AI1 样本并更新编码器位置差分：
   - 低电平时继续向回收方向运动。
   - 第一次读到高电平后立即执行 `x_speed(0)`，不再发送负向速度命令。
5. 在 X 轴保持停止的状态下继续读取新鲜 AI1 样本：
   - 首次高电平计为第 1 个触发样本，再采集剩余样本，只有连续 5 个高电平才确认稳定触发。
   - 任一样本回落为低电平都保持停止并返回 `False`，不得恢复运动。
   - 静止确认期间的超时、传感器异常或串口异常均返回 `False`。
6. 运动阶段：
   - 编码器连续停滞只作为失败，不得建立零点。
   - 超时、传感器异常、串口异常均作为失败。
7. 只有静止状态下稳定触发的成功路径可以读取当前电机位置并写入 `x_pose_start`，随后把 `x_pose_now`、`x_pose_last` 和 `x_distance_change` 清零并返回 `True`。
8. 所有失败路径返回 `False`，不修改 `x_pose_start`。
9. `finally` 无条件执行 `x_speed(0)`，并恢复普通水平移动使用的 PID 输出范围和 PID 状态。

归零使用恒定低速命令，不再调用以虚拟位置 `-0.33` 为目标的 `x_pid_moveto()`。这样成功条件只来自独立机械开关，PID 到位与编码器停滞均不能成为成功条件。`reset_x()` 本身只负责建立机械零点并停止在触发点；启动流程随后调用 `retract_x_safe()` 离开开关，因此两种动作的成功条件不会混在一起。

## `reset_position()` 失败传播

当前 `reset_position()` 在线程中调用 `reset_x()` 后丢弃返回值，并继续执行 `self.x = 0`。这会在启动高电平或传感器故障时吞掉归零失败。

设计要求在线程包装函数中保存 X 轴动作的布尔结果。`rehome_x=True` 时依次执行 `reset_x()` 和 `retract_x_safe()`；`rehome_x=False` 时只执行 `retract_x_safe()`。两个重置线程结束后：

- X 轴动作成功时才允许继续位置保存和结束遥测；删除现有的 `self.x = 0`。该属性的 setter 会再次下发位置运动，而安全回收完成后 getter 已经会从编码器读出约 `15 mm`，不能在已经离开开关后又命令水平轴返回触发点。
- X 轴动作失败时再次停止 X 轴，并在保存位置前抛出 `RuntimeError`，使当前忽略返回值的调用方也能停止后续流程。

## 错误处理与日志

失败日志必须区分：

- 启动未稳定松开；
- 读取不到新鲜样本；
- 传感器数值无效；
- 编码器停滞；
- 归零超时；
- 未预期异常。

成功日志记录 AI1 端口、最终原始值和稳定样本数。日志不得声称断线与真实按下已经被软件区分。

## 验证边界

按用户要求，本阶段不执行 TDD 红绿循环，不新增或运行大范围测试，也不运行真实开关、电机寻零或 `move_x_position()`。实现后的本地验证仅限：

- 审查精确 Git diff，确认不覆盖其他工作树改动；
- 静态语法检查，不导入硬件栈；
- 静态检查所有退出路径均包含 X 轴停止，且只有稳定触发成功路径修改 `x_pose_start`。

真实硬件归零和位置运动必须等待用户另行明确授权。
