# 单前摄黄线巡线校正与任务边距标定设计

## 目标

在不增加摄像头的前提下，复用现有前置摄像头，对连续、同一侧、清晰延伸至画面下部的黄色直线进行测量，为车辆提供：

- 车体参考点到黄线的物理横向距离；
- 车身相对黄线的航向误差；
- 可用于控制决策的检测置信度；
- 正常直道巡航时的横向与航向校正；
- 任务点停车后相对黄线的可配置边距标定。

最终实车目标为车辆参考点到设定边线距离的综合误差不超过 3 cm。第一阶段采用 HSV 黄线提取完成最小闭环；第二阶段可将像素提取后端替换为轻量黄线分割 CNN，而不改变标定、几何、控制和任务接口。

## 已确认前提

- 使用正常巡线时同一种、同一侧的连续黄色地面线。
- 本功能只在已确认的直线路段启用，不处理弯道、路口或黄线中断路段。
- 车辆正常居中时，黄线在前摄 640×480 原图下方约三分之一范围内清晰可见，并延伸到画面底部附近。
- 现有 `LaneInfer` 继续承担原有基础巡线与回退职责。
- 麦克纳姆底盘可分别控制前进速度、横移速度和旋转速度。
- 纵向任务点仍由里程计、任务标志或目标检测确定；单条直黄线不能提供沿线纵向位置。

## 非目标

- 不训练图像直接输出转向或横移指令的端到端校正模型。
- 不在第一阶段训练或部署新的 CNN。
- 不自动替换 `car_task_function.py` 中所有 `lane_dis_offset()` 调用。
- 不使用黄线测量替代目标检测的最终物体对齐。
- 不承诺在弯道、交叉线、黄线缺失或摄像头支架移动后继续满足 3 cm 精度。

## 现有系统约束

正式任务的前摄由 `Camera` 以 640×480 默认分辨率采集。现有 `LaneInfer` 在推理前把画面缩放为 128×128，并只输出 `error_y` 和 `error_angle`。这两个回归值可以驱动现有双 PID，但不能直接解释为车辆到黄线的厘米距离。

现有巡线控制链为：

```text
cap_front -> LaneInfer -> error_y/error_angle -> lane_pid -> set_velocity(vx, vy, wz)
```

`lane_dis_offset(speed, dis_hold)` 当前按累计里程决定结束条件；`dis_hold` 是前进距离，不是横向边线距离。新设计保持该接口的旧调用行为，并通过可选参数显式启用物理黄线控制。

当前侧摄像头承担任务目标检测与视觉对齐，因此本设计不占用侧摄像头，不增加第三路 USB 视频流。

## 总体架构

```text
                         +-> LaneInfer -> legacy errors ------+
front camera 640x480 ----+                                    +-> one PID owner -> chassis
                         +-> YellowLinePoseEstimator ----------+
                                  |
                                  +-> distance_m
                                  +-> heading_rad
                                  +-> confidence
```

两条感知支路共享同一前摄原始帧，但任一时刻只有一个误差源拥有 `Vy/Wz` 控制权。禁止把原 CNN PID 输出与黄线 PID 输出直接相加。

## 组件设计

### 1. 帧获取

控制循环每次只读取一次前摄并立即复制，确保原 CNN、黄线估计器、录像和遥测使用同一逻辑帧。黄线支路使用 640×480 原图；原 CNN 保持现有 128×128 预处理。

帧为空、尺寸与标定尺寸不符或时间戳无效时，黄线估计器返回显式无效结果，不输出可用于运动控制的旧测量值。

### 2. 黄线像素提取接口

感知后端采用可替换接口：

```python
class YellowMaskProvider:
    def predict(self, frame_bgr) -> YellowMaskResult:
        ...
```

`YellowMaskResult` 包含与输入图像同坐标系的概率或二值掩码、后端名称、耗时和基础质量指标。

第一阶段实现 `HsvYellowMaskProvider`：

1. 对已标定原图去畸变；
2. 裁剪约定侧黄线的梯形 ROI；
3. 转换到 HSV，必要时结合 Lab 的亮度/黄色通道；
4. 使用配置化阈值分割黄色区域；
5. 用小尺度开运算去除散点，用闭运算连接局部断裂；
6. 删除面积、宽度或位置明显不合理的连通区域。

阈值、核大小和 ROI 均来自配置，不散落在任务代码中。自动曝光变化明显时，允许基于 ROI 亮度做有限的阈值补偿，但不得每帧无界自适应到任意黄色物体。

第二阶段新增 `CnnYellowMaskProvider`。它只替换上述像素提取步骤，输出同一接口，不修改后续几何和控制代码。

### 3. 相机标定与地面映射

标定固定使用 640×480：

- 用棋盘格完成相机内参和畸变标定；
- 在赛道地面布置至少 6 个已知车辆坐标点，覆盖近场和中场 ROI；
- 以车辆地面参考点为原点计算图像到地面的单应矩阵；
- 用未参与求解的检查点验证重投影后的厘米误差；
- 保存标定分辨率、相机矩阵、畸变系数、单应矩阵和参考点定义。

车辆参考点使用车体几何中心在地面的投影。机械臂、吸嘴或其他执行机构相对车体中心的偏移属于任务配置，不写入相机标定。摄像头支架、焦距、分辨率或俯仰角变化后，原标定作废。

### 4. 黄线几何估计

将黄线掩码中的有效像素映射到车辆地面坐标系。在限定的近场到中场范围内，使用 RANSAC 或等价鲁棒拟合得到地面直线。采用法向式而不是只依赖图像斜率，以稳定计算：

- 车辆参考点到黄线中心线的有符号法向距离 `distance_m`；
- 黄线方向与车辆前进轴之间的 `heading_rad`；
- 拟合残差、内点比例、可见长度和近场覆盖。

黄线距离统一以中心线为基准。若任务定义使用黄线内侧边缘，则通过已测量的黄线物理宽度换算目标值，不在像素掩码中临时选择左右边缘。

### 5. 输出与置信度

```python
YellowLinePose(
    valid: bool,
    distance_m: float | None,
    heading_rad: float | None,
    confidence: float,
    reason: str,
    timestamp: float,
    diagnostics: dict,
)
```

置信度综合以下证据：

- ROI 内黄线有效面积与可见长度；
- 近场是否有足够覆盖；
- RANSAC 内点比例和物理拟合残差；
- 黄线宽度及宽度变化是否合理；
- 候选区域是否位于约定侧；
- 与最近有效帧的距离、角度变化是否合理；
- 是否存在两个难以区分的强候选。

原因字段至少区分 `ok`、`no_line`、`low_coverage`、`ambiguous_candidates`、`fit_failed`、`measurement_jump`、`frame_invalid` 和 `calibration_mismatch`。

滤波只作用于已通过几何检查的测量。初版采用短窗口中值滤波加轻量指数平滑；窗口和系数通过录像测量延迟后确定。不得用长时间持有上一帧结果掩盖黄线丢失。

## 控制模式

### `LEGACY_LANE`

保持现有 `LaneInfer -> lane_pid` 行为，所有旧调用默认进入该模式。

### `YELLOW_FOLLOW`

用于已明确标记的连续黄线直道。前进速度仍由调用方给出；黄线测量提供：

```text
distance_error = measured_distance - target_edge_distance
heading_error = measured_heading
```

单一双通道 PID 输出 `Vy/Wz`。进入黄线控制前需要连续 3～5 帧达到接管置信度；退出采用较低阈值和连续帧计数形成迟滞。切换误差源时清除 PID 积分，并对第一阶段控制量做变化率限制。

推荐兼容接口：

```python
lane_dis_offset(speed, dis_hold, stop=STOP_PARAM, edge_offset_m=None)
```

`edge_offset_m is None` 时行为与现在完全相同；传入物理目标距离时才请求 `YELLOW_FOLLOW`。只有逐段确认是连续黄线直道的任务调用可以传该参数。

巡航时黄线短暂失效可受控回退到 `LEGACY_LANE`。回退前清除积分、限制命令跳变并记录原因；无法得到任一有效感知结果时停车。

### `YELLOW_ALIGN`

任务纵向位置到达并停车后执行精确横向与航向校准：

```python
align_to_yellow_edge(
    edge_offset_m,
    distance_tolerance_m=0.015,
    heading_tolerance_deg=1.5,
    timeout_s=5.0,
) -> EdgeAlignResult
```

该模式固定 `Vx=0`，以较低限幅控制 `Vy/Wz`。建议初始限幅为 `|Vy| <= 0.08 m/s`、`|Wz| <= 0.30 rad/s`，最终数值由低速实车测试确定。

到位必须同时满足：

- 距离误差不超过 1.5 cm；
- 航向误差不超过 1.5°；
- 横移与旋转命令均处于小输出区；
- 连续稳定至少 10 个有效控制帧。

精确校准中黄线低置信度时立即禁止继续横移和旋转。短暂等待后仍不能恢复则停车并返回失败，不允许静默回退到无法保证物理距离的原 CNN。

`EdgeAlignResult` 包含成功状态、结束原因、最终测量、误差、置信度和耗时。失败原因至少包括 `line_not_found`、`low_confidence`、`timeout`、`stop_requested`、`camera_failure` 和 `control_error`。

## 配置设计

配置分成全局标定、感知控制参数和任务目标距离：

```yaml
yellow_line:
  enabled: false
  side: right
  frame_size: [640, 480]
  mask_backend: hsv

  calibration:
    camera_matrix: []
    distortion: []
    image_to_ground_homography: []
    vehicle_reference_offset_m: [0.0, 0.0]

  hsv:
    roi: []
    lower: []
    upper: []
    open_kernel: 3
    close_kernel: 5

  confidence:
    enter: 0.65
    exit: 0.40
    acquire_frames: 5
    lost_frames: 3

  follow_control:
    max_vy: 0.20
    max_wz: 0.60

  align_control:
    max_vy: 0.08
    max_wz: 0.30
    distance_tolerance_m: 0.015
    heading_tolerance_deg: 1.5
    stable_frames: 10
    timeout_s: 5.0

task_edge_offsets: {}
```

空标定或 `enabled: false` 时不得进入黄线控制。示例中的控制值是保守初值，不是未经实车验证即可用于正式任务的最终参数。每个任务边距必须现场测量后写入配置，禁止以未标定示例值代替。

## 与任务流程的关系

典型流程为：

```text
按里程/标志进入任务区域
    -> 可选 YELLOW_FOLLOW 保持物理边距
    -> 停车
    -> YELLOW_ALIGN 建立稳定车体基准
    -> 原 move_to_detection_target 完成目标最终对齐
    -> 执行抓取、识别、射击或放置
```

黄线校准优先改善任务到达时的横向与航向一致性，减少目标进入侧摄视野前的硬编码横移和视觉搜索时间。它不替代纵向里程，也不保证目标本身相对黄线的位置恒定。

首个接入任务选择 `auto_seeding`：入口流程短，只有一次主要巡线，并且现有代码包含固定横移补偿，便于做旧方案与黄线基准方案的 A/B 对比。初次接入只记录黄线测量，不删除现有补偿；只有实车证据确认黄线测量能解释并稳定替代该补偿后，才单独移除对应常量。

其他任务按风险逐项启用，不做全文件机械替换。弯道、绕行和无法确认黄线连续性的 `lane_dis_offset()` 调用继续使用 `LEGACY_LANE`。

## 安全与故障处理

- 所有实车控制入口在首个运动命令前验证相机、标定、输出形状、有限值和置信度。
- `Ctrl+C`、停止标志、超时、相机失败、配置错误和测量异常均进入停车清理路径。
- 精确校准中不使用无效帧或过期测量继续运动。
- 每次感知源切换和目标距离变化都清除 PID 积分。
- 第一阶段黄线控制仅允许低速、短时、有界测试；正式任务启用需要独立验收。
- 感知置信度不能替代外部真实距离测量，3 cm 结论必须来自物理测量。

## 遥测与可诊断性

每个控制帧记录：

```text
timestamp, mode, mask_backend, confidence, valid, reason,
distance_m, target_distance_m, distance_error_m,
heading_rad, fit_residual_m, visible_length_m, inlier_ratio,
legacy_error_y, legacy_error_angle,
vx_cmd, vy_cmd, wz_cmd, pid_source, switch_reason
```

调试视频叠加 ROI、黄线掩码、拟合线、地面参考点、距离、角度、置信度和当前控制模式。录像帧号必须与逐帧 CSV 对齐，便于从异常命令回查原始画面。

## 验证与验收

### 本地自动化验证

- 单应变换、点到直线距离、角度和符号方向的合成数据单元测试；
- HSV 后端在固定图像上的掩码与质量指标测试；
- 空帧、尺寸错误、无黄线、双候选和测量跳变的拒绝测试；
- 置信度接管/退出迟滞和 PID 重置测试；
- 旧 `lane_dis_offset()` 调用保持原行为的兼容性测试；
- `YELLOW_ALIGN` 到位、超时、停止和失线状态机测试；
- 配置缺失或空标定时禁止进入运动模式的测试。

### 静态物理标定验收

在多个真实边距和小角度组合下采集静态图像。距离点至少覆盖目标值附近及其左右偏差，航向至少覆盖正负方向。使用独立尺具测量真实距离，不以里程计或视觉自身输出作为真值。

进入运动闭环前要求：

- 目标工作区内静态距离绝对误差的 95 分位不超过 1.5 cm；
- 静态航向绝对误差的 95 分位不超过 1.5°；
- 无黄线和黄色干扰物场景不产生高置信有效线；
- 不同光照批次分别报告结果，不混合掩盖最差条件。

### 实车分阶段验收

1. **只读模式**：显示和记录黄线测量，不下发车辆命令。
2. **影子模式**：原 CNN 控制，记录两套误差、耗时和置信度。
3. **低速巡航**：独立直道，速度不超过 0.10 m/s，验证失线停车/回退。
4. **静止校准**：从左右偏移和正负偏航的多种起始姿态进入同一目标边距。
5. **单任务 A/B**：先在 `auto_seeding` 比较到位误差、对齐耗时、检测失败率和最终任务成功率。
6. **逐任务扩展**：每次只增加一个已确认直道路段或一个任务边距。

3 cm 最终验收采用多次重复试验，报告中位数、95 分位和最大误差。建议正式通过条件为至少 95% 试验不超过 3 cm，且不存在失线后继续横移、控制源相互对抗或未停车退出。

## 第二阶段：轻量分割 CNN 扩展

当 HSV 方案完成几何和闭环验证，但在目标光照范围内不能满足置信度或 3 cm 指标时，再训练二分类黄线分割模型。

优先使用 PaddleSeg 的轻量预训练网络进行微调，而不是从零训练。数据必须覆盖居中、左右偏移、正负偏航、阴影、强光、曝光变化、磨损、遮挡、运动模糊、黄色干扰物和无有效黄线负样本。训练集与验证集按采集批次或完整视频段划分，禁止把同一连续片段的相邻帧随机分到两边。

可用 HSV 结果生成初始掩码，再人工修正以降低标注成本。CNN 输出黄线概率掩码并实现 `YellowMaskProvider` 接口；单应性、直线拟合、置信度、状态机、PID、任务接口和验收方法保持不变。

CNN 上线前必须与 HSV 后端在同一离线数据集和同一实车路线做 A/B。只有在最差光照下提高有效检测率，同时不增加黄色干扰物误检和推理超时，才替换正式后端。HSV 可保留为辅助一致性检查，但不得在两者严重冲突时盲目选择任一控制结果。

## 实施边界

本设计文档只确定架构、接口、安全边界和验收标准，不授权实车运动、现场标定、模型训练或修改现有任务行为。后续实施计划应把感知纯函数、离线标定工具、状态机测试、只读/影子模式和低速实车验证拆成独立阶段，并在任何正式任务接入前完成用户审核。
