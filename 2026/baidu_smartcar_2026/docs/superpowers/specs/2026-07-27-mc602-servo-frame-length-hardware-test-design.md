# MC602 舵机帧长度硬件对照测试设计

## 目标

改造 `testangle.py`，通过项目现有的 MC602 自动识别和机械臂控制栈，对总线舵机的 angle8 与 angle16 两种帧格式做单变量硬件对照。每次运行只测试一种格式；两次测试使用相同的寻零、水平位置、端口、速度和目标角度。

测试目标固定为：

- 水平轴位置：`0.25 m`
- 总线舵机端口：`2`
- 舵机速度：`60`
- 目标角度：`RIGHT=-92°`
- angle8 完整帧长度：`0x0A`
- angle16 完整帧长度：`0x0B`

## 方案

只修改测试脚本，不修改生产协议表或机械臂控制实现。

`testangle.py` 接受必填参数 `--angle-bytes {1,2}`。脚本创建 `ArmController`，使用标准驱动完成 MC602 识别和设备初始化。随后按以下顺序执行：

1. 确认当前控制器是 MC602；否则退出。
2. 调用 `reset_x()` 触达机械回收端并建立物理零点；失败则退出。
3. 调用 `move_x_position(0.25)`；失败则退出。
4. 打印实际 X 位置、测试格式、端口、速度、角度和预期完整帧。
5. 等待操作者确认机械空间安全。
6. 仅在测试脚本内，将底层 `ServoBus_2.data_struct` 设置为对应格式：
   - angle8：`StructData("bbbbb")`
   - angle16：`StructData("bbbbh")`
7. 调用现有 `ServoBus.set_angle(-92, 60)` 一次。
8. 打印底层 `last_data` 和翻转后的 X 编码器位置，供现场记录物理动作与通信结果。

直接调用 `ServoBus.set_angle()`，而不是 `ArmController.set_arm_angle()`，是为了避免当前工作树的三次经验性重发影响帧长度对照。两种格式都只发送一次。

## 安全与错误处理

- 测试前机械臂必须无负载，周围无人员和障碍物，并可随时断电。
- `reset_x()` 或 `move_x_position(0.25)` 返回 `False` 时，不发送舵机命令。
- 舵机发送前必须由操作者在终端明确确认。
- `finally` 中始终调用 `x_speed(0)`，撤销水平轴输出。
- 测试结束不自动回收水平轴。舵机命令失败时实际方向未知，自动回收可能引入额外碰撞风险。
- angle16 与 angle8 必须分两次进程运行，建议先测当前生产/Gitee 使用的 angle16；两次之间给 MC602 和舵机断电重启。
- 测试只允许在 `/home/jetson/workspaces/baidu_car_2026_official_run_copy/` 运行，禁止同步或运行到 `/home/jetson/workspaces/baidu_smart_2026_7_17/`。

## 输出与判定

每次运行至少输出：

- 控制器名称；
- `reset_x()` 结果；
- `move_x_position(0.25)` 结果及实际 X 位置；
- angle8/angle16 选择；
- 预期 TX 完整十六进制；
- 舵机底层 `last_data`；
- 翻转后的 X 编码器位置。

现场另行记录舵机是否实际到达 RIGHT，以及是否出现抖动、异响、USB 重枚举或 MC602 重启。

判定原则：

- angle16 能稳定翻转而 angle8 不能：当前固件更支持 Python/Gitee 的 2 字节角度格式。
- angle8 能稳定翻转而 angle16 不能：协议表的 1 字节角度格式更符合当前固件。
- 两者都失败但水平寻零和移动成功：MC602/X 通信成立，继续检查舵机端口、供电、接线和返回行为。
- 两者都成功：帧长度不是“不翻转”的充分根因，继续测试重发、锁等待和时序。

## 自动验证

增加不连接硬件的测试，验证：

1. angle8 生成长度字节 `0x0A`，角度 `-92` 使用一个有符号字节；
2. angle16 生成长度字节 `0x0B`，角度 `-92` 使用 little-endian int16；
3. 未选择合法格式时拒绝运行；
4. 寻零失败或 X=0.25 移动失败时不调用舵机；
5. 成功路径严格遵循“寻零 → 移动 X → 人工确认 → 单次舵机命令”；
6. 所有退出路径都撤销 X 轴速度。

硬件动作不进入自动测试；自动测试只覆盖帧构造、控制顺序和失败保护。
