# CV 控制等效曲率训练设计

## 目标

让 CNN 学习 OpenCV 教师最终执行的转向动作，同时保持模型接口尽量简单。
推荐的转向输出是由已知前进速度作为条件的“动作等效曲率”。CNN 应能够
学习正常巡线、右锐角处理、断线保持和启动阶段的转向行为。车端后处理不应
再次执行 CV 的转向梯度或右锐角覆盖逻辑。

## 最终双输出接口修订（2026-08-16）

最终模型输出确定为：

```text
[speed_demand, kappa_action]
```

`speed_demand` 是 CV 教师保存的归一化弯道强度，范围为 `0～1`，用于车端可调
速度曲线生成 `target_vx`；`kappa_action` 是包含 CV 角速度渐变、启动保护、断线
保持和锐角处理后的最终动作曲率。运行时只执行：

```text
target_vx = speed_curve(speed_demand)
actual_vx = real_dt_speed_slew(target_vx)
wz        = actual_vx * kappa_action
vy        = 0
```

本文后续单独写作“CNN 输出 `kappa_action`”的段落属于此前单输出讨论，均以本节
双输出接口为准。正常赛道保持和偏移归位由 `kappa_action` 完成；未来只有确认
转向归位不足时，才考虑增加共享主干的 `vy_action` 第三输出。

CV 与手柄 session 统一保留 `state/control=[vx,vy,wz]`，不得再复用 `state` 存放
模型标签。模型监督单独保存在 `model_target={speed_demand,kappa_action}` 和
`target_mask`。CV 使用 `[1,1]`；手柄数据从实际 `vx,wz` 生成动作曲率，但人工
油门不作为 CV 速度曲线监督，因此默认使用 `[0,1]`。混合训练必须逐输出应用
mask，不能用手柄样本中的占位速度需求计算损失。

## 标签定义

每张图像都使用 CV 全部逻辑执行后的最终教师命令。原始底盘命令是统一的
标准标签，曲率是派生训练字段：

```text
kappa_action = control.angular_speed /
               max(abs(control.forward_speed), 0.12)
```

其中 `control.angular_speed` 已经包含断线保持、右锐角处理、启动保护、角速度
限幅和当前教师动作。数据写入时必须保留：

```text
control.forward_speed
control.lateral_speed
control.angular_speed
target_forward_speed
valid / held
source_reason
timestamp_monotonic
source = cv 或 joystick
```

旧的 `control_error_angle` 可以继续作为诊断字段，但不再作为首选训练接口。

## CV/CNN 运行流程

```text
图像 + vx 条件
    ↓
CNN 输出 kappa_action
    ↓
根据曲率计算目标速度
    ↓
按真实 dt 执行速度加减速梯度
    ↓
wz = actual_vx × kappa_action
    ↓
底盘安全限幅
    ↓
输出 vx, 0, wz
```

曲率是速度规划和底盘角速度控制的共同接口。原始几何曲率只用于诊断，不能
直接作为动作训练标签，因为它不包含断线保持和特殊弯道行为。

## 已知前进速度条件

CNN 不需要从图像估计速度。`vx` 由速度规划器或编码器提供，有两种实现方式：

1. 将归一化后的 `vx_condition` 与视觉骨干特征拼接，再输入曲率输出头；
2. 保持当前图像模型不变，在控制适配器中使用已知 `vx` 将曲率转换为 `wz`。

当速度变化较大时，方案 1 更稳定；固定赛道且速度规划确定时，方案 2 对现有
模型改动更小。

训练同时使用动作损失和可选的曲率约束：

```text
kappa_label = control.wz / max(abs(target_vx), 0.12)
wz_pred     = target_vx × kappa_pred
loss        = SmoothL1(wz_pred, control.wz)
              + lambda_kappa × SmoothL1(kappa_pred, kappa_label)
```

`wz` 是最终发送给底盘的控制量，因此 `wz` 损失为主，曲率损失为辅，不能让
曲率损失主导低速样本。运行时使用实际测得的 `actual_vx` 计算 `wz`，而
`target_vx` 只用于教师标签和速度规划。本设计假定 `vy = 0`；若以后启用横移，
必须重新定义曲率和底盘转换关系。

## 速度控制和真实时间

所有速度梯度都必须使用单调时钟测量的真实 `dt`，不能按帧数固定加减：

```text
dt = monotonic_now - last_time
dt = clamp(dt, dt_min, dt_max)
vx_next = move_towards(vx_previous, target_vx, rate_per_second × dt)
```

首帧使用接近标称 20 Hz 的默认周期。丢帧时将 `dt` 限制在安全范围内，并记录
实际使用的 `dt` 供离线回放。CV 教师和 CNN 推理必须共用同一套时间控制器，
推理频率不能改变转向或速度建立速度。

## 后处理边界

由于右锐角、断线保持和启动行为已经进入训练标签，推理后不得再次执行：

```text
pure_pursuit_entry_step
max_heading_release_step
max_heading_reverse_step
route_right_turn_override
```

推理后只允许安全限幅、watchdog 超时停车和通信异常保护。任何会改变 `wz`
行为的处理都必须被视为控制器逻辑，并同步写入 CV 教师标签。

启动图像在固定赛道上被视为具有唯一视觉特征，因此启动阶段的零转向应由 CNN
学习。若实车验证发现启动图像与正常跑圈图像不可区分，再增加启动进度输入或
连续帧输入，而不是重新加入隐藏的帧数延迟。

## 标准数据记录方式

原始数据永远保留统一动作格式：

```text
control = [vx, vy, wz]
```

曲率只是可重新计算的派生字段，因此后续手柄补充采集仍然可用。每条记录应包含：

- `source`：`cv` 或 `joystick`；
- `valid`、`held`；
- 教师原因或手柄状态；
- 单调时间戳；
- 图像采集时间、命令发送时间和端到端延迟；
- 用于曲率转换的 `target_vx`。

手柄恢复数据应单独统计或降低损失权重，不能未经区分地当作 CV 标准轨迹，
因为手柄数据通常包含偏离赛道后的救车动作。

## 数值和低速保护

- `vx`、`kappa`、`wz` 使用固定且文档化的归一化范围，并随模型检查点保存；
- 曲率换算使用最小速度分母，禁止直接除以接近零的瞬时速度；
- 曲率输出和最终 `wz` 都必须设置有限幅；
- 低速样本以 `wz` 损失为主，避免曲率数值过大导致训练不稳定；
- 如果未来允许 `vy != 0`，不能继续直接使用当前的 `wz / vx` 定义。

## 延迟和数据对齐

必须测量相机采集到命令实际执行之间的延迟，并将图像与延迟之后真正执行的
命令对齐。高速弯道中，使用当前帧立即发送的命令作为标签会造成系统性提前或
滞后。若延迟随负载变化明显，应使用短序列输入或在训练中加入延迟状态。

## 使用旧图片离线重标注

旧手柄或旧采集 session 的图片可以交给 CV 教师重新回放，生成新的 CNN
训练标签：

```text
旧数据集图片
    ↓ 按完整序列和原始顺序回放
CV 教师重新处理
    ↓
生成 control、kappa_action、target_vx 等标签
    ↓
训练 CNN
```

离线重标注不能逐张图片独立执行。每圈开始时必须重置控制器状态，并按原始
帧顺序处理，因为断线保持、速度梯度、启动阶段、右锐角候选和上一帧转向都
具有历史依赖。应优先使用原始单调时间戳；没有时间戳时使用固定的标称周期，
并在 `session.json` 中明确记录。

CV 重新生成最终 `wz` 时需要速度来源：

- 如果旧数据有可靠的手柄 `vx`，可以记录该速度并重新计算动作曲率；
- 如果没有可靠速度，应使用 CV 的曲率到速度规划器重新生成 `target_vx` 和
  速度梯度。此时标签代表 CV 速度策略，不代表旧手柄当时实际执行的速度。

重标注结果不得覆盖原始数据，应建立独立 session，例如：

```text
lap_001/
  images/
  original_controls.json

cv_relabelled_lap_001/
  images/                    # 可引用原图
  controls.json              # CV 重标注结果
  session.json               # CV 参数、版本和时间策略
  replay_diagnostics.json
```

每条记录至少保存图像引用、时间戳、原始 session、`control.vx/vy/wz`、
`kappa_action`、`target_vx`、`valid`、`held`、教师原因和 CV 配置哈希。

来自手柄救车阶段的图片不能无条件接受 CV 标签。重标注后应根据线段质量、
有效性、曲率突变、输出限幅和检测原因筛选；检测失败或动作明显不适合当前
图像的样本应剔除或单独作为恢复数据集。重标注时必须锁定 ROI、透视参数、
曲率参数、速度范围、速度梯度、`dt` 限制、右锐角规则、断线保持规则和启动
处理版本，否则同一图片会产生不可复现的标签。

离线重标注适合扩充样本、统一旧图片标签和批量比较 CV 参数，但不能完全替代
真实 CV 采集，因为旧图片不包含新控制策略下的真实速度、底盘姿态和执行延迟。

## 训练与验证

验证集按完整 session 或完整赛道圈划分，不能随机打散相邻帧。至少同时报告：

1. `wz` 符号和幅值误差；
2. 曲率误差；
3. 入弯和回正位置；
4. 右锐角与断线保持窗口；
5. 启动阶段转向；
6. 速度趋势和真实时间梯度；
7. 推理频率、`dt` 和端到端延迟；
8. 完整闭环轨迹回放结果。

只有在离线回放的动作趋势、距离时序和特殊窗口均通过后，才进行低速实车测试。
