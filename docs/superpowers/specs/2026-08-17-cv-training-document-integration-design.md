# CV 教师与 CNN 训练文档整合设计

日期：2026-08-17

## 目标

将 `docs/lane-cnn-training-handoff.md` 设为 CV 自动采集、CNN 训练和车端部署的唯一当前入口，使接续开发者仅阅读这一份文档即可理解当前数据语义、控制链、兼容策略和验收流程。

`docs/cv-lane-development-status-2026-08-15.md` 继续保留为 CV 视觉算法、赛道帧段分析和参数演进的完整历史记录。

## 整合原则

1. 不复制整份 CV 开发日志，只提取训练和部署必须掌握的稳定结论。
2. 当前实现与历史方案明确分层，旧的 `[vy, yaw_error]` 方案不得继续被描述为最终接口。
3. 所有数据字段、计算公式和 profile 名称必须与当前代码一致。
4. 保留手柄数据补充能力，明确 CV 与手柄样本不同的 `target_mask`。
5. 训练文档必须能独立回答“如何采集、如何生成标签、如何训练、如何部署、如何验收”。

## 文档结构

### 训练交接文档

- 更新顶部状态：工作树、分支、当前提交和文档权威边界。
- 在最终模型接口附近给出当前闭环摘要。
- 新增“CV 教师—训练—部署闭环”章节，包含：
  - CV Pure Pursuit 教师输出与实际底盘命令；
  - 原始统一格式 `[vx, vy, wz]`；
  - 模型目标 `[speed_demand, kappa_action]`；
  - `wz = vx * kappa_action`；
  - CV 与手柄样本的 `target_mask`；
  - 基于真实 `dt` 的速度和角速度梯度；
  - `legacy_error` 与 `kappa_action` profile；
  - 旧图片离线重标注、训练、导出和实车验收步骤；
  - 关键代码索引和检查清单。
- 将第 16～18 节定位为决策演进，并明确第 18 节及新增闭环章节代表当前结论。

### CV 开发状态文档

- 在顶部增加权威文档说明和相互链接。
- 保留全部赛道实验、帧段分析、参数变化和历史结论。
- 不在此文档重复维护训练字段定义，避免两处内容再次分叉。

## 非目标

- 不修改 CV、CNN 或底盘控制代码。
- 不删除已有实验历史。
- 不补写尚未存在的完整训练工具或虚构训练结果。
- 不把本地未跟踪实验脚本纳入当前正式流程。

## 验收标准

1. 训练交接文档明确给出当前分支与代码入口。
2. 数据格式、模型标签、mask、后处理公式与代码完全一致。
3. 历史方案不会被误读为当前部署方案。
4. 两份文档互相链接且权威边界清晰。
5. 文档不存在未决占位符或相互矛盾的最终结论。
